# gpui-kit landmines and ops

The kit is not CSS. Do not revert.

1. **`h_flex()` is `flex().flex_row().items_center()`.** Not the mirror of `v_flex()`. A content-tall column in an `h_flex` body is vertically centered, covers the TitleBar, never shrinks, and `overflow_y_scroll` sees `scroll_max = 0`. Body row is `div().flex().flex_row().items_stretch()`. Sidebar and `#main` use `h_full()` + `min_h_0`.
2. **Page scroll is three layers** in `Shell::page_scroller`: `#page-slot` (`flex_1` + `min_h_0` + `overflow_hidden`), `#page` (`size_full` + `overflow_y_scroll` + `track_scroll`), `#page-content` (`flex_none`). Putting `overflow_y_scroll` on the `flex_1` column itself lets Taffy size children to the viewport → wheel does nothing.
3. **Do not use `overflow_y_scrollbar()` as that flex item.** The kit wrapper always applies `size_full()`; nested wrong it collapses the main pane. Wheel-only is the current choice.
4. Sidebar list is a `v_virtual_list` (own viewport, independent of the page scroller). `v_virtual_list` makes a fresh `VirtualListScrollHandle` per frame and GPUI takes the scroll offset from that handle, so the list snaps to the top unless you keep a persistent handle and `.track_scroll(&shell.sidebar_scroll)`. Row height must be exact (`Shell::sidebar_row_h`); rows are positioned, not stacked.
5. gpui-kit `Input` needs a live `InputState` entity — one search box is fine; per-knob text fields are not.
6. `Button` has `.secondary()` / `.ghost()`, not `.outline()`. `.selected()` needs `Selectable as _`. `.on_click` must return the button, not `()`.
7. `cx.spawn` on `Context` takes `(this, cx)`; App spawn takes one. Click paths that hit sqlx go through `background_spawn`, not `rt_block` on the UI thread.
8. **`Tab` renders the label only when no icon is set.** `Tab::render` matches on `self.icon`; the `Some` arm draws the icon alone and the label/children branch is the `None` arm. For icon + label use `.prefix(icon)` + `.label(text)` and keep the accessible name via `.aria_label(label)`. Do not use the icon slot: it centers the glyph in a 27.5px box while the label text sits flush, so the underline overhangs left of the visible content. `prefix`/`suffix` are rendered regardless of the icon.
9. **Two icon sets.** `gpui_component::IconName` is the 101-icon default set; the full Lucide catalog is `gpui_kit::assets::IconName` (1830). The default asset source serves only the 101, so a catalog-only icon (`Boxes`, `Trash`) needs `icon_assets!(ExtraIcons, [Boxes, Trash])` composed with `gpui_kit::assets::Assets` (`gui::Assets`). `AllAssets` would embed the whole 7 MB catalog.
10. Kill the GUI with **`killall tuxgt`**. `pkill -f 'tuxgt gui'` matches the wrapper argv and SIGTERM’s itself.
11. **Linux CSD.** `gui/chrome/run/build.rs` uses `TitleBar::window_options()` and sets `window_decorations = Client`. The product bar is custom (`titlebar.rs` owns drag/zoom and the right-click menu). Do not use kit `TitleBar`: its `WindowControls` hardcode Close hover `danger`. Custom min/max/close at kit 34px size, muted-circle hover on all buttons, Client only. Do not paint a second min/max/close cluster. `chrome_btn` `stop_propagation`s on down/click/double-click so owned `BarDrag` never steals button gestures. Kit `WindowBorder::BORDER_RADIUS` is **0**; 10px corners = clip the inner Shell (`overflow_hidden` + radius) in `gui/render.rs`; 0 when tiled/maximized. Window chrome stays opaque. If Client is refused, stop — do not ship double close buttons.
12. **Dialog vs homemade overlay.** Kit `WindowExt::open_dialog` is the Mods install picker; the app view must also render `Root::render_dialog_layer` (`Root`'s own render paints no dialogs) — and that builder then runs **inside `Shell::render`**, so reading the Shell it is rendered from panics (`entity_map.rs`, "cannot read … while it is already being updated"). Capture the rows and copy before `open_dialog` (`Strings` is not cloneable), keep live widget state in its own entity, and keep `read`/`update` on the view inside event handlers, which run outside render. `open_sheet` is the fallback only if Dialog cannot host the checkbox list. Do not add a custom side panel or bottom drawer first.
13. **History is in-session.** Back/forward is not `ui.toml`. Inner TabBar pushes a history entry, so back/forward cross tabs. Do not persist a history stack. Titlebar buttons must `stop_propagation` on left-down or owned `BarDrag` starts a window move and the click is lost.
14. **`ToggleGroup` owns its children’s clicks.** Its render overwrites each child `Toggle`’s `on_click` with its own recorder, so a per-child handler never runs — the segment paints and hovers but is inert. `ToggleGroup::on_click` then gets the whole next-check vector with the clicked segment flipped (the group is not exclusive: re-clicking the active segment flips it off). Diff `next` against the checks you rendered to find the click (`gui/settings/` Load|Include).
15. **Kit `Button::on_click` does not stop propagation.** A button inside a clickable row or card bubbles to the parent handler (a trash control on a row also activates the row). `cx.stop_propagation()` at the head of the inner handler is required.
16. **Read kit sources before adopting a kit widget.** Limits visible in the kit source: `TitleBar` always appends `WindowControls` with Close hover hardcoded to `danger`; `Sidebar` fights app scroll and paint; `field()` + `h_form()` do not replace the app's label/control rows. Read kit `title_bar.rs`, `sidebar/`, and `form/` first. The kit is primitives plus `cx.theme()` until a spike proves a widget fits.
17. **One tokio runtime and one DB pool per GUI process.** `gui::rt_block` blocks on a single shared `multi_thread` runtime, and loaders open the DB with `open_db_shared` — one `SqlitePool` per data dir. `reconcile_mod_cache` runs at every open; only the pool is shared. Do not open a runtime or a fresh `open_db` per call: sqlx spawns one OS thread per connection and glibc keeps each short-lived thread's arena pages resident. CLI and the other tests keep `open_db`. GUI start calls `set_trim_threshold()` (`gui/chrome/run/mod.rs`): glibc's default trim threshold holds those freed arena pages.

`GameTab` default is **General**. Do not default to Mods or Environment.

Sticky page chrome: Library filters and Game header+tabs sit **above** the scroller (`page_chrome` `flex_none`). `scroll_page_top()` on nav / game / tab change.

## Ops

- Run: `cd src/tuxgt && cargo build -p tuxgt --offline -q && ./target/debug/tuxgt gui`. CLI must still work with no display.
- Restart: `killall tuxgt` then launch. Do not leave duplicates.
- **GUI verify lane** (the default for agents): `src/tuxgt/tools/gui-session start --seed` brings up a private headless-sway session and runs the worktree binary as a Wayland client on a scratch prefix. Then `shot [--window]`, `find TEXT` → `X Y`, `click X Y`, `scroll up|down`, `type`, `key`, `logs`, `stop`. Nothing appears on the operator's desktop, input cannot reach it, and lanes are independent (`--id`) so several validate at once. Commands: tool header.
- Lane rendering is software-only: `LIBGL_ALWAYS_SOFTWARE=1`, Mesa llvmpipe EGL, Vulkan disabled by default (`--vk lavapipe` opts in). The wgpu Vulkan loader ERROR lines in `app.log` are that choice, not a render failure.
- Operator session, Wayland-only surfaces only (CSD frame vs compositor, tiling/maximize, Settings Host DE/compositor line, keyring Secret Service): the gpui window there is Wayland — `xdotool`/`wmctrl` do not see it; screenshots via `spectacle -m -b -n -o /tmp/...png`.
- The lane has no session bus and no X server: keyring steps and anything reading the operator's session env are out of scope there (`--bus` passes the session bus through when that is the point of the check).
- Prefs: `$PREFIX/config/ui.toml`. Safe default for shots: `theme = "tuxgt-dark"`, `font_scale = "default"`.
- Tests: `cargo test` and `cargo deny check` in `src/tuxgt/`. The `tuxgt` bin has no GUI tests.
- Writes: only the repository root and `/tmp/`. `external/` is read-only. Do not copy Stitch HTML into `src/tuxgt/`.
