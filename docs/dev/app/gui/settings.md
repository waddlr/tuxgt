# Settings

Stitch ref: `tux_gt_preferences_engine_settings/` minus skipped blocks.

Inner pages: underline TabBar in the main pane (same kit as Game tabs; **not** titlebar). **General** | **Core Plugins** | **Game Env** | **Mods**. `settings_tab` in `ui.toml` restores the last inner tab; `settings_mods_tab` (`optiscaler` | `reshade` | `custom`, default `optiscaler`) restores the Mods inner tab.

Library and Settings remain sidebar jumps. Back/forward leave Settings. Empty-library **Configure paths** still opens Settings.

**Remember inner tab** (`gui.settings-return`): `ui.toml` `settings_tab` = `general` | `core-plugins` | `game-env` | `mods` (`docs/dev/app/gui/tokens.md`). Missing or unknown → **General**. Changing the Settings TabBar writes the key. Re-entering Settings restores it. Persist across restarts. Do not default to Core Plugins, Game Env, or Mods when nothing is saved. The Mods inner tab persists separately in `settings_mods_tab`. Game inner tab is not this key.

Titlebar context: `Settings` on General; `Settings / Core Plugins`, `Settings / Game Env`, or `Settings / Mods` otherwise.

- **General** — two columns. Left (top to bottom): About, Appearance, Tray, Rendering, TuxGT Install. Right (top to bottom): Library, Host Tools, Host. No plugin or Mod lists. No API-credentials card (the SteamGridDB key editor lives on its plugin card under Core Plugins). No Maintenance section. No bottom status bar.
  - **About** (left column, top) — section title, then icon + TuxGT, muted `v{version} · {build date}` (`CARGO_PKG_VERSION`, `VERGEN_BUILD_DATE`), and a Repo link. Then install dir + open; logs dir (`<data>/logs/`, rolling daily) + open; debug-logging switch (`ui.toml debug_log`, read at next start when `RUST_LOG`/`TUXGT_DEBUG` are unset). No update button on this tree (`app.self-update` Missing; the button is specified in `install.md` Self-update). No Paths card (data + config opens); Steam/Heroic roots stay auto-discovered at scan, no editor.
  - **Appearance** — theme preset (`tuxgt-dark` first, then `tuxgt-dark-blue`, `tuxgt-light`, `tuxgt-light-blue`, then the rest), **Density** (`font_scale`: Compact / Default / Comfy; `large` remains the stored id). Live apply.
  - **Host** (`gui.settings-host`) — right column, under Host Tools. OS · kernel, DE · compositor · session, CPU, RAM, GPU. Same probes as `sys.rs`; identity, not meters. `detect.gpu` stays for Env Advance.
  - **TuxGT Install** (`gui.settings-host-install`) — left column, under Rendering. Host-file manager for the current prefix. Status from the host-install verify report: ok, or one row per non-ok intended path (`path` + state); the 9 themed icons collapse to one `icons <ok>/9` + status row. A missing inventory says so and still lists intended-path failures. **Install** runs `tuxgt install --yes` to `data_dir()` (unpackaged dev binary errors, no write); a `modified` path confirms first via the confirm card (it will overwrite ours). **Uninstall** runs `tuxgt uninstall --yes`, always confirms (PATH links + boot conf); PREFIX stays. Either op toasts the outcome via `pending_note` and refreshes the report; the drift list is the persistent view. No new Settings tab.
  - **Library** (`gui.scan-inventory`) — right column, top; **Rescan libraries** (`Shell::rescan`; runs `harvest_all` after scan, same as CLI `tuxgt scan`) sits in the Library header (top right). **Total** = `self.games.len()` (unfiltered index, including hidden rows; not the search-filtered sidebar). **Per first-party GameProvider** `steam` / `heroic` / `manual`: count of rows whose `manager` matches, even if the plugin is now disabled (rows stay). Show all three, zero is fine. Display names are Steam, Heroic, and Manual, not raw ids. Do not count Mods here. No titlebar Rescan. No second Rescan on Core Plugins. Empty-library Steam/Heroic cards may still run `rescan` (store CTAs, not titlebar chrome).
  - **Host Tools** (`gui.settings-tools`) — right column, under Library. Unpack PATH tools from `all_tools()` in `EXT_TOOLS` order (`unzip`, `unrar`, `7z`, `tar`). One row per entry: binary name, short what-for (zip archives / RAR / 7z and ReShade Setup / tar archives), pill **found** (mint) or **missing** (danger), version first line when found. Probe **once when opening Settings** (same moment as `reload_secrets`). Do not re-exec on paint. No refresh button (leave and re-enter Settings). Missing is honest; we do not install packages, sudo, or open a distro store. `7zz` alias is not probed. Wrappers (MangoHud / GameMode / gamescope) are Launch, not this block. CLI `tuxgt cache tools` unchanged.
- **Core Plugins** (`gui.settings-core-plugins`) — PluginHost rows grouped by category (`docs/dev/app/plugin/host.md`). Every row is a property row (name + id left, enable toggle right). Enable/disable via the same `list` / `set_enabled` as CLI. No Lutris row.
  - **Game Manager / Store** — Steam, Heroic, Manual.
  - **Metadata Providers** — ProtonDB, SteamGridDB, AWACY. Every Core Plugins row keeps the enable toggle as its last/right control; the SteamGridDB gear precedes that toggle and opens the panel under the row (a disclosure, not a header peer). The card hosts the key editor (`gui.keyring-set`): key in the **system keyring** (never plain-text config; never rendered back). Pill `set` / `not set` is the stored-or-not signal. **unset:** masked input + Save + Test. **set:** pill + Test + Clear + **Edit** — no empty input. **editing:** masked empty input + Save + Cancel (Cancel → set, no write). Empty Save → error, no write. After Save, clear the input widget. Test uses the keyring entry, not the field. Probes `GET https://www.steamgriddb.com/api/v2/search/autocomplete/portal` and reports valid / rejected / error; the key is never logged. `tuxgt metadata key set steamgriddb` still works. Not “KWallet Linked”. Off until set. No fake `••••` placeholder.
  - **Capabilities** — Game Env (`env`), Wrappers (`wrapper`).
  - **Mods** — official ReShade / official OptiScaler rows are the same property row (enable = offered). Not `plugins.toml` ids. No `plugin_id()` on Provides. Do not add PluginHost ids `reshade` / `optiscaler`.
  - **Registries** — Later (`gui.plugin-registry`). Do not ship a placeholder. This page hosts add-registry → list plugins → install when that surface lands.
- **Game Env** (`gui.settings-env`) — global EnvKnobs (same groups as the game Env tab). **Label = env var** (`DXVK_HUD`, not `dxvk-hud`). Two axes: **set/unset** and **enabled/disabled** (disabled keeps the value, omits it from session/launch). Main groups always open; collapsed **Advance** holds other-GPU vendor groups (host `detect.gpu`) unless the knob is set/unmanaged. Unmanaged: live value, disabled, **not writable**. Globals apply on the next injected Play (Hook/Apply/manual), not via session restart. Freeform values are CLI (`tuxgt env global set`). Not `env_custom`. Not wrappers.
- **Mods** (`gui.settings-mods`) — catalog of Mod definitions. Never per-game Instances (those live on the Game Mods tab).
  - **OptiScaler** — official Mod row (property row, enable only), then user Mods that Provide OptiScaler as object cards.
  - **ReShade** — official Mod row (property row, enable only), then user Mods that Provide ReShade as object cards: one list (addons + shaders + textures).
  - **Custom Mods** — out-of-box `d3dcompiler_47` row, then user Custom Mods as object cards.
  - **User Packs** — on the ReShade tab, one `User Packs` section header carries three Add buttons in order **ReShade, HDR, Custom** (`Add ReShade Pack`, `Add HDR Packs`, `Add Custom Pack`; no leading Plus — the cluster collapses to `⋯` when the header wraps; no separate `Packs` or `HDR packs` section headers).
  - **HDR packs** (`gui.family-mint`) — opened from the User Packs header `Add HDR Packs` action (both families merged; templates absent → button hidden). Click opens the mint card as a page takeover (game picker pattern: tab lists hide while open, page scrolls to top): merged live asset lists (each row badged RenoDX/Luma; a failed vendor still lists the other with its error shown; fetched fresh from the GitHub release API on every open, no cache) in a capped viewport (ten two-line rows) with its own scroll (wheel over it scrolls only the list, chaining to the page at its limit). Above the list, **Select Visible** in the 24px column covers the filtered rows only (off-filter picks survive). Each row auto-matches a library game (vendor prefix stripped, exact tokens; single hit pre-checks, else unchecked) with a per-row game value button (`value_btn`) the user corrects (picking a game checks the row); label is always auto. **Add** mints every checked row with a game (`family_template` + `snap_family_asset` + `RecipeSpec::family` + `mint_recipe`) — resolved AppID → `appids = [id]` + no games, else games glob + no appids — writes `$PREFIX/mods/user/<id>.toml` per asset, stops on first error, and re-lists the catalog with a minted-vs-skipped toast (no-game rows named, nothing written for them). **Cancel** writes nothing. No manual asset/AppID/Title entry. Game page unchanged: minted Mods install from the existing picker.
  - **ReShade packs** (`gui.reshade-packages`) — opened from the User Packs header `Add ReShade Pack` action. One button opens a takeover card (game picker pattern: tab lists hide while open, page scrolls to top): live `EffectPackages.ini` + `Addons.ini` (`list_reshade_packages`, fresh every open), **All / Effects / Addons** filters, filter box, then a **Select Visible** checkbox (`gui-action-select-visible`) in the 24px checkbox column, tracking exactly the visible/filtered selectable rows (no-URL + already-in-catalog excluded), then checkbox + name + description rows in a capped viewport (twelve rows) with its own scroll (wheel over it scrolls only the list, chaining to the page at its limit); `Repo` is an `open_btn` Link (URL is its tooltip). Already-in-catalog and no-URL rows are listed, not selectable (locked). The card requires a target game (one `value_btn` over the library above the list; its effective bitness picks the arch) and rows lock per-arch for that target — a missing arch URL or a locked variant stays listed, not selectable. Each row paints its qualified `x32`/`x64` identity. No target → **Add** names the missing target and writes nothing (retryable). Default all unchecked (catalog mint, not the installer's Required/Enabled defaults). **Add** mints every newly checked row for the target arch (`RecipeSpec::reshade_package_for_game` + `mint_recipe`; one recipe each; stop on first error; toast); a package's un-suffixed legacy recipe migrates to `B-x64` first (conflict → error, nothing written). **Cancel** writes nothing. Per-`.fx` checkboxes and preset-path auto-select are out (Game Mods keep switches omit dests). Game page unchanged: minted Mods install from the existing picker.
  - **Add** (`gui.custom-mod-add`) — single `Add Custom Pack` button, no extension filter. Scan-first type inference: `effect` unless a `.addon64`/`.addon` file is present (then `reshade_addon`); mixed addon+shader packs mint as `reshade_addon` with `.fx` files kept archive-relative. Mixed allowed (`App::can_select_mixed_files_and_dirs()`): `files: true, directories: true`. Else a **File | Folder** popover, then that kind. Never set both portal flags when mixed is false. Same classify after. The Add form is a page takeover. When open, the tab lists hide so only the form shows and the page scrolls to top; the file tree sits in a capped box (twelve rows) with its own scroll (wheel over the box scrolls only it, chaining to the page at its limit). Cancel, Save, or switching tabs closes it (draft dropped, nothing written until Save). Rescan uses the same panel (title `Rescan <id>`, no Name field). **Name** is the single field (id slug source + label); no shared Mode switch. Multi-file picks get a two-pane source/dest tree: left column is a checkbox per row in the 24px column (first row is **Select Visible** when more than one file — checked iff all rows checked, hidden for a single file); right column is a per-row dest input on checked rows and empty (no destination) on unchecked rows — no shared dest inspector. Kept DLL rows carry the segmented **Load | Include** (`ToggleGroup.outline().segmented()`) on the right, on Add **and** Rescan: Rescan seeds it from the recipe `include` list and Save persists the form's include dests through `rescan_mod`. **Slot** is auto-detected at save from the kept dests (no Slot field). **Requires** value button (`value_btn`) with checkboxes on addon-family types — Save stays blocked until a ReShade Mod is picked, and the template never fills a text field. Save writes `$PREFIX/mods/user/<id>.toml` and copies the payload into `$PREFIX/mods/user/<id>/`. Honor a recipe's `type`; jump to that Settings Mods tab.
  - **Re-sync official** — catalog chrome button: reload packaged Mods/Templates without restart (needed after `make deploy` with the app open). **Remove visible** (trash, tooltip) removes the user catalog rows listed on the current inner tab (ReShade: user ReShade cards plus the filtered User Packs list). Official recipes stay. Confirm first.
  - **Details** — every catalog card (official and user) drops the id subtitle and carries one ghost **Details ▸** in the header cluster. The open body is a fixed two-column grid (Id, Kind, Type, Slot, Plans, Fetched, Size, Status, Checked; empty cells omitted), then full-width Source, a fetched URL only when it differs from the recipe source, Requires, and Installed / Not installed when no game has the mod. Lists of one or two entries stay inline; longer lists share one row of `▸ N` buttons, in order: Applies to, Include, Remap, payload rules, Env, Effects, Files, installed game names. Applies to uses library display names and one "{n} not in your library" token, never a raw Steam id. Effects only when the recipe is an effect with effect files. Files is the kept-payload list (effect names removed; a single archive name already shown on Source or the URL is omitted; empty walk says it needs install). An open nested list caps at 10 names, then `+ N more` / Show less. Edit stays on config rows in Files, and on Include and Effects for a non-official mod that has a payload. The game picker and the per-game card keep their own Files / Effects buttons.
  - **Export** (`gui.mod-export`) — every user-Mod card carries Export: **Recipe** writes the recipe TOML, **Recipe + files** bundles TOML + kept payload srcs as a `.tar.gz`; both go through a save picker (`<id>.toml` / `<id>.tar.gz` suggested). Official cards have no Export button.
  - **Update badges** — poll-fresh Available paints a warning note + primary **Update** on official **and** user cards. Update refreshes the catalog payload only (`acquire` redownload; no manifest touch, so game Instances stay Available until the game-card Update). Officials stay enable-only otherwise.
  - **Config edit** (`gui.mod-config-edit`) — every allowlisted text config in a user-Mod Files preview carries icon-only Edit (file-pen-line): the tab takes over for a full-page kit Textarea editor (Save/Cancel) + Open externally. Opening externally closes the page; refocus refreshes from the external level. Navigating away closes the page the same way (clean closes silently, unsaved edits park a Discard confirm). Save rewrites the payload file and auto-pushes to installed games (non-force; per-game touches preserved with a status note). A per-game Update redownload replaces those payload bytes without a confirm and keeps per-game staged touches. Official rows stay enable-only: no Settings Edit.
