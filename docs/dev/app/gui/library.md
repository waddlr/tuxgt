# Library

Stitch refs: `library_all_titles/`, `library_no_games_detected/` (rewrite copy; drop Lutris / Flatpak-of-Tux-GT).

- Filter bar: **Store**, **Platform** (runner family × observed graphics API: `Windows - All`, `Windows - DX12`, `Linux - Vulkan`, …; values `{family}` or `{family}:{api}` with `windows` = `proton` or `wine` and `native` shown as Linux; unset platform matches no family row, unset API matches the family row only), ProtonDB, Active mods, Anti-cheat, **Show hidden** (effective-hidden games are hidden by default; a disabled provider's games stay hidden regardless). Sort: A–Z, mod count, ProtonDB, **Recent** (`last_played` DESC, never-played last). Grid/list toggle. Store options are `manager:store` pairs (store may be empty). Label is the store name when that store id appears under one manager; `{store} - {manager}` when the same store id appears under more than one; empty-store rows use the manager label (Steam / Heroic / Manual). Filter **values** stay ids; other menus and chips show display labels (DX12, Vulkan).
- **Add manual game** — GUI entry removed. Existing `manual:standalone:*` rows stay listed. CLI `tuxgt games add <exe>` stays. Manual rows offer **Remove**: confirm card → `remove_manual`; the list row and grid overlay paint it as the trash (`destroy_btn`, word as tooltip). Steam/Heroic rows never offer it.
- **Grid (dynamic cover box, max 200×300):** 2:3 Steam capsule. Live `w` from ceil-packed columns under the page width (as many columns as needed so slack is absorbed by shrinking; exact N×200+(N−1)×12 stays 200), `h = w × 3/2`, both capped at 200×300, `w ≥ 40`; width quantized to 4px. Box size freezes while the ceil-pack target is moving and settles ~120ms after that target stops changing. Covers paint from the pre-rendered grid thumb (400×600 physical, 2:3 center crop, `download.artwork`) GPU-scaled into the live box. Idle: cover (or initials), no chips, no caption, no pristine/modified dot. Hover overlay: dark scrim; **title** top-left; stacked pills **bottom-left** top→bottom Store (muted, same Store-filter label rules, no store colour), ProtonDB **tier only** (no “ProtonDB ” prefix; omit if missing/`none`), AWACY (matched), API (detected); **Unmodded** / `{n} mods` bottom-right; centre **Play** (page CTA) + **Game**, plus trash on manual rows. **No** id triple, Proton string, exe path, or `(stock)`. Game page ProtonDB chip still uses `ProtonDB {tier}`.
- **List (horizontal, fixed row):** 48×32 thumb, title, chips, mod count, trash on manual rows (last in the cluster). Click opens Game.
- **Empty (no games):** Steam / Heroic cards only. Drop the Manual card (title/body/action). No Lutris, no Bottles, no Faugus, no `flatpak override` for a TuxGT Flatpak. CTA: provider Rescan + **Configure paths** (opens Settings).

Card click or left-nav click opens **Game** and writes `last_game` + `view = "game"`. No selection: `last_game` if still listed, else first, else empty prompt.

**Pristine vs modified:** modified if any TuxGT mod is enabled, or we wrote the game dir, or we Applied launch options. Small dot. No extra column.

Last played: every successful Play (Library card + Game hero, incl. enable-and-play) persists `games.last_played` via `touch_last_played` (scan never writes it). A **Recently Played** strip (top-5, visibility-filtered, sort-independent) sits above the grid; **Recent** sort orders `last_played` DESC with never-played last (A–Z tiebreak). Manual plugin enable/disable (Settings) is unchanged; a disabled plugin still hides new `games add` per `game-provider.md`; existing rows stay.
